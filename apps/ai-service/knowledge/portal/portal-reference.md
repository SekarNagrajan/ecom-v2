# portal — portal behaviour and reference

Generated by scripts/ingest_ecom_mocks.py from the portal's own configuration, settings, status codes, notification catalogue, workflow emails and policy content.

## Portal behaviour: Shipping instruction document types (SHIPPING_INSTRUCTION_DOCUMENT_TYPES)

The document types a shipping instruction may carry, in display order. JSON array of {documentCode, documentName, requiredForDangerousGoods}. Every document is optional; requiredForDangerousGoods marks one a dangerous-goods shipment must carry.

## Portal behaviour: Shipment tracking access (SHIPMENT_TRACKING_ACCESS)

PUBLIC: any caller tracks any shipment. PRIVATE: only a signed-in customer who is a party on the shipment's latest document (manifest correction note, else B/L, else booking).

## Portal behaviour: Shipping instruction party functions (SHIPPING_INSTRUCTION_PARTY_FUNCTIONS)

The party blocks the shipping instruction screen shows, as a JSON array of objects: code is the custTypeId, name is its label, required marks a party every save must carry. A save refuses a party not listed here.

## Portal behaviour: Shipping instruction reference types (SHIPPING_INSTRUCTION_REFERENCE_TYPES)

The references the shipping instruction screen collects, in display order. JSON array of {referenceCode, referenceName, inputType TEXT|DROPDOWN, required, validation, options, appliesTo}, as BOOKING_REFERENCE_TYPES.

## Portal behaviour: Dashboard history, days back (SHIPMENT_HISTORY_DAYS)

How many days back the Tasks screen, Shipment Overview and their home tiles reach when no dates are picked. Everything ahead is always included.

## Portal behaviour: Shipping instructions window, days ahead (SHIPPING_INSTRUCTION_SUMMARY_DAYS_AHEAD)

How many days after today the Shipping Instructions overview ends, by departure from the port of loading. Not applied when a booking number is searched.

## Portal behaviour: Shipping instructions window, days back (SHIPPING_INSTRUCTION_SUMMARY_DAYS_BACK)

How many days before today the Shipping Instructions overview starts, by departure from the port of loading. Not applied when a booking number is searched.

## Portal behaviour: Booking reference types (BOOKING_REFERENCE_TYPES)

The references the booking screen's Additional information section collects, in display order. JSON array of {referenceCode, referenceName, inputType TEXT|DROPDOWN, required, validation, options, appliesTo}. Published to the UI as stored; the UI filters by route and validates.

## Portal behaviour: Customer default menu access (CUSTOMER_DEFAULT_MENU_KEYS)

The menus a customer is granted when their registration is approved. JSON array of EcomMenu.menuKey values of menuType CUSTOMER, including each CUSTOMER parent group. GLOBAL menus need no grant. Affects customers approved afterwards only.

## Portal behaviour: Booking document types (BOOKING_DOCUMENT_TYPES)

The document types a booking may carry, in display order. JSON array of {documentCode, documentName, requiredForDangerousGoods}. Every document is optional; requiredForDangerousGoods marks one a dangerous-goods booking must carry.

## Portal behaviour: Contact us recipients (CONTACT_US_RECIPIENTS)

The inboxes every contact-us inquiry is mailed to, as a JSON array of addresses.

## Portal behaviour: Login customer type (LOGIN_CUSTOMER_TYPE)

The roles the signed-in customer holds on the bookings its recent parties are read from: AP,BP or AP. Passed as it stands to @custConfigType of usp_getEcomLastestCustomerFromBooking, which removes parties whose custtypeid equals this value.

## Portal behaviour: Booking party functions (BOOKING_PARTY_FUNCTIONS)

The party blocks the booking screen shows, as a JSON array of objects: code is the custTypeId, name is its label, required marks a party a submitted booking must carry. Bookings keep only these parties; the recent-parties dropdown accepts only these codes.

## Portal behaviour: Preferred agency display names (PREFERRED_AGENCY_NAMES)

The name shown for each agency code in the preferred-agency dropdown. JSON object keyed by agency code. A code with no entry here is published with a null name, which is a configuration gap rather than a valid state.

## Portal behaviour: Preferred agencies by port (PREFERRED_AGENCIES_BY_PORT)

Which agencies a booking at each port may be placed with. Keyed on the booking ORIGIN port (place of receipt, ecombooking.originPortId), not the port of loading. JSON object keyed by UN/LOCODE in upper case, each value an ordered array of agency codes - the first is the default for a new booking. A port absent from this object offers no choice.

## Portal behaviour: Captcha site key (CAPTCHA_SITE_KEY)

The public captcha key a client initialises its widget with. Published by GET /api/v1/application-settings. Paired with CAPTCHA_SECRET_KEY, which is not published.

## Portal behaviour: Display date format (DISPLAY_DATE_FORMAT)

Pattern a client should display a date in. A DISPLAY pattern only - this API always serialises a date as ISO-8601 and this row does not change that. Must be a pattern java.time.format.DateTimeFormatter can read, or the settings endpoint refuses it.

## Portal behaviour: Application title (APPLICATION_TITLE)

The name a client labels the application with - browser tab, page heading, screen header. A deployment decision; edit it rather than accepting the seeded default.

## Portal behaviour: Ports excluded from schedules (RESTRICTED_SCHEDULE_PORTS)

UN/LOCODEs that must not appear in any schedule result. A port call at one of these is dropped before the response is built, so the port is invisible to every schedule screen. JSON array of codes; an empty array [] excludes nothing.

## Portal behaviour: Carrier code (ECOM_CARRIER_CODE)

The carrier this platform operates as. Sent as carrierCode on every mail, where it decides the branding the integration API applies. Not specific to any one flow.

## Portal behaviour: Ecommerce integration API username (ECOM_INTEGRATION_USERNAME)

Service account this platform authenticates to the integration API as, over HTTP Basic.

## Portal behaviour: File upload maximum size in MB (FILE_UPLOAD_MAX_SIZE_MB)

Largest single file any upload endpoint accepts, in megabytes. Whole number, greater than zero.

## Portal behaviour: File upload allowed extensions (FILE_UPLOAD_ALLOWED_EXTENSIONS)

File extensions any upload endpoint accepts. JSON array of strings, lowercase, no leading dot.

## Portal behaviour: Country calling codes (COUNTRY_CALLING_CODES)

International dialling prefixes for telephone and mobile number fields. JSON array of { callingCode, countryCode, countryName }. Order is the display order. Served by GET /api/v1/master-data/country-calling-codes.

## Portal behaviour: Registration reCAPTCHA enabled (REGISTRATION_RECAPTCHA_ENABLED)

When on, a registration must carry a reCAPTCHA response token and it is verified with Google before anything is stored. While off the token is neither required nor checked.

Current state in this environment: **OFF**.

## Portal behaviour: Shipping instructions for confirmed bookings only (SHIPPING_INSTRUCTION_CONFIRMED_BOOKING_ONLY)

When on, the Shipping Instructions overview lists only confirmed bookings. When off, it lists accepted and confirmed bookings.

Current state in this environment: **OFF**.

## Portal behaviour: Accepted booking cancellation hidden (LRP_BOOKING_CANCEL_HIDDEN)

When on, the booking list does not offer the CANCEL action on a booking the agency has accepted but not yet confirmed. Note this one reads the opposite way round to the others: on means the action is hidden.

Current state in this environment: **ON**.

## Portal behaviour: Confirmed booking cancellation enabled (CONFIRMED_BOOKING_CANCEL_ENABLED)

When on, a confirmed booking can be cancelled: the booking list offers the CANCEL action on it, and a booking whose cancellation request is still with the agency reads as Cancellation Submitted. Requires the ecom_statusdescription row for status X - see the script header.

Current state in this environment: **OFF**.

## Portal behaviour: Confirmed booking amendment enabled (CONFIRMED_BOOKING_EDIT_ENABLED)

When on, a confirmed booking can be amended: the booking list offers the AMEND action on it, and hides the confirmed row while an amendment is in flight so the submitted row is the only one shown.

Current state in this environment: **ON**.

## Portal behaviour: Booking summary shows all LRP cancellations (BOOKING_SUMMARY_SHOW_LRP_CANCELLED)

When on, every carrier booking the agency rejected reads as Cancelled on the booking list. When off, only those raised online do; a rejected carrier booking with no online reference is left off the list entirely.

Current state in this environment: **OFF**.

## Portal behaviour: Preferred agency enabled (PREFERRED_AGENCY_ENABLED)

When on, a booking at one of the configured ports asks the customer which agency owns it, and that choice overrides the agency derived from the port. When off, no port offers a choice.

Current state in this environment: **ON**.

## Portal behaviour: Cargo protect enabled (CARGO_PROTECT_ENABLED)

When on, the booking flow offers cargo protect where the voyage allows it. When off, no voyage offers it and the Cargo Protect step shows nothing.

Current state in this environment: **ON**.

## Portal behaviour: Multiple agency setup enabled (AGENCY_MULTIPLE_SETUP_ENABLED)

When on, the controlling agency for a port is resolved per sail date through the ecommerce integration API instead of being taken from the agency master.

Current state in this environment: **ON**.

## Portal behaviour: Vessel list restricted to mainline vessels (VESSEL_MASTER_SHOW_MAINLINE_ONLY)

On: only vesseltype MAINLINE is returned. Off: every vessel type.

Current state in this environment: **OFF**.

## Portal behaviour: Port Master - Show Sea Ports (PORT_MASTER_SHOW_SEA_PORTS)

When enabled, restricts the result to sea ports by adding the porttype = 'P' filter. Independent of the routing setting.

Current state in this environment: **OFF**.

## Portal behaviour: Port Master - Show Routing Ports (PORT_MASTER_SHOW_ROUTING_PORTS)

When enabled, ports come from routings active today (routedetail joined to ports); when disabled, from the plain ports master.

Current state in this environment: **ON**.
